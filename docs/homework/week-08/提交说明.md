## 1. 选择一个跨服务业务流程

我的社区报修项目采用提交报修、审核、派单和接单流程。报修服务在创建工单前调用住户服务校验住户，在派单和接单时调用维修人员服务校验人员及技能；各服务只读写自己的数据库。已在服务通信文档中给出调用方、被调用方、接口路径及 Mermaid 调用链路图。

## 2. 使用 OpenFeign

已将报修服务跨服务访问改为 OpenFeign，按服务名从 Nacos 发现实例，配置连接与读取超时并禁止自动重试。保留 404/409 等业务错误，无实例或依赖不可用时返回 503，不绕过校验保存工单。

上传：`screenshots/01-feign.png`，可同时上传 `screenshots/03-workflow.png`。

## 3. 负载均衡验证

已启动两个均注册为 user-service 的住户服务实例，宿主机端口为 8091 和 8094。测试只向报修服务 8093 发请求，通过被调用实例实际返回并由 Feign 转发的响应头，验证六次请求实际访问到了 user-1 与 user-2，均返回 HTTP 200 和同一住户的数据。

上传：`screenshots/02-load-balancing.png`。

## 4. 测试

报修服务 24 项、住户服务 4 项测试在 Windows 和 Docker 构建中通过。根目录执行 bash scripts/e2e-test.sh 已验证完整业务流程、双实例分发和失败恢复。住户两个实例停机时返回 503，工单数保持 18 条；恢复后成功创建并查询工单 20，脚本退出码为 0。超时可能导致远端写入结果未知，应先查询确认。
