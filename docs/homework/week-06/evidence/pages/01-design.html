三个服务，三个独立数据边界

来源：docs/microservices-design.md / compose.yaml
服务端口独立数据库 / 账号自有表职责
user-service8091user_db / user_appresidents住户档案
technician-service8092technician_db / technician_apptechnicians维修人员、技能、可接单信息
repair-service8093repair_db / repair_apprepair_orders提交、审核、派单、接单

通过 HTTP 协作

repair-service
本地事务 / 工单状态
→ RestTemplate →
user-service
校验住户存在
repair-service
派单前校验
→ RestTemplate →
technician-service
人员存在 / 技能 / 可接单

仅保存外部 ID；不建立跨库外键，不直接访问其他服务 Repository。

monolith/ 保留单体；services/ 下每个服务都有独立 pom.xml、src/ 和配置。

一致性边界

远端 GET 成功与本地提交不是原子操作；校验后资料可能改变，本地提交也可能失败。当前不实现分布式事务、自动补偿或消息。
