# 邻里修：可视化界面操作流程

项目：社区报修与上门维修服务平台

演示主线：新建报修 → 物业审核 → 安排维修人员 → 确认接单 → 查询结果。

## 一、启动与访问

1. 启动 VMware 中的 Ubuntu 虚拟机。
2. 在 Windows 浏览器打开 [工单工作台](http://192.168.158.128:8093/)。
3. 页面加载完成后，确认右上角显示“数据已连接”。

如果网页打不开，在 Ubuntu 终端执行：

```bash
cd ~/community-repair-week07
sudo docker compose up -d
sudo docker compose ps
```

等待服务启动后刷新网页。Ubuntu 内部也可以访问 `http://localhost:8093/`。Windows 必须使用虚拟机的 IP；如果虚拟机 IP 变化，应替换访问地址中的 IP。

## 二、准备演示档案

已有“陈同学（演示）”和“周师傅（演示）”时，可直接使用，不必重复创建。

### 新增住户

1. 点击左侧“住户档案”。
2. 点击右上角“新增住户”。
3. 填写姓名和联系电话。
4. 点击“确认提交”，确认档案出现在列表中。

示例姓名：`陈同学（演示）`。联系电话使用尚未登记过的测试号码，重复号码会返回错误。

### 新增维修人员

1. 点击左侧“维修人员”。
2. 点击“新增维修人员”。
3. 填写姓名和未登记过的联系电话。
4. 维修技能选择“水管维修”，接单状态选择“可接单”。
5. 点击“确认提交”，确认人员出现在列表中。

示例姓名：`周师傅（演示）`。如果新增了同名档案，后续通过联系电话或编号辨认。

讲解提示：

> 住户和维修人员档案分别由对应服务保存。这里登记的是业务档案，不是登录账号。

## 三、新建报修

1. 点击左侧“工单工作台”。
2. 点击右上角“新建报修”。
3. 填写以下内容。

| 字段 | 演示填写内容 |
| --- | --- |
| 报修住户 | 陈同学（演示） |
| 报修位置 | 3 幢 302 室 · 厨房 |
| 维修类型 | 水管维修 |
| 问题描述 | 厨房水槽下方管道漏水，请安排维修。 |

4. 点击“确认提交”。
5. 成功后查看弹出的工单详情，确认状态为“待审核”。
6. 记住页面生成的工单编号，后续始终操作同一条工单。

讲解提示：

> 提交时，报修服务通过 Nacos 发现住户服务的实例地址，发送 HTTP 请求确认住户存在，再将工单保存到自己的数据库。

截图建议：填写完成、尚未提交的新建报修表单，或提交成功后的“待审核”详情。

## 四、物业审核

1. 在刚才的工单详情中，点击“审核通过”。
2. 填写审核说明：

```text
已核实漏水情况，同意安排维修。
```

3. 点击“确认提交”。
4. 确认状态变为“待派单”，审核说明已经显示。

讲解提示：

> 只有待审核的工单可以审核。审核通过后才能派单，状态流转由后端 Service 检查。

截图建议：同一工单的“待派单”详情，保留工单编号和审核说明。

如果选择“驳回报修”，工单会进入“已驳回”，不能继续派单。完整流程演示应选择“审核通过”。

## 五、安排维修人员

1. 在工单详情中点击“安排维修人员”。
2. 在下拉列表中选择“周师傅（演示）”，或其他水管技能且可接单的人员。
3. 点击“确认派单”。
4. 确认状态变为“待接单”，详情显示已分配的维修人员。

讲解提示：

> 页面只列出技能匹配且可接单的人员。后端会通过服务发现调用维修人员服务，再次检查人员状态和技能，不能只靠前端筛选。

截图建议：选中维修人员后的派单窗口，或派单成功后的“待接单”详情。

如果没有可选人员，先检查是否已登记对应技能、状态为“可接单”的维修人员。新增后点击“刷新数据”，重新打开派单窗口。

## 六、确认接单

1. 在工单详情中点击“确认接单”。
2. 核对弹窗中的人员与之前分配的人员一致。
3. 点击弹窗中的“确认接单”。
4. 确认工单状态变为“已接单”，进度显示已到达确认接单步骤。

讲解提示：

> 当前模拟被分配的维修人员确认接单。至此完成报修受理流程，但已接单不代表维修完工，完工和住户验收仍未实现。

截图建议：同一工单的“已接单”详情，保留编号、维修人员、审核说明和处理进度。

## 七、查询与展示结果

1. 关闭工单详情。
2. 在搜索框输入刚才生成的工单编号，也可以输入住户姓名、报修位置或故障关键词。
3. 用“状态”筛选选择“已接单”。
4. 用“类型”筛选选择“水管维修”。
5. 点击“查看详情”，核对状态、住户和维修人员。
6. 清空搜索框、恢复全部状态和类型，即可返回完整列表。

可点击顶部统计项快速筛选对应状态，使用列表底部按钮翻页。

讲解提示：

> 页面可以按编号、住户或故障信息查找工单，并结合状态和维修类型筛选，便于查看处理进度。

## 九、课堂展示顺序

| 步骤 | 展示内容 | 讲解重点 |
| --- | --- | --- |
| 1 | 工作台统计和列表 | 集中查看报修需求和处理状态 |
| 2 | 新建报修 | 服务发现校验住户，保存工单 |
| 3 | 审核通过 | 状态变化受后端规则约束 |
| 4 | 安排维修人员 | 技能匹配且可接单 |
| 5 | 确认接单 | 同一工单完成受理流程 |
| 6 | 搜索并查看详情 | 结果可重新查询，数据真实保存 |

3 分钟汇报建议主要讲 PPT，现场用约 30 秒展示工作台和 BX-0011 的详情。如果要现场从头操作完整流程，应先排练，并相应压缩讲稿。

## 十、异常提示与功能边界

- **页面无法访问：** 检查虚拟机是否启动、IP 是否变化，以及容器运行状态。
- **数据加载失败：** 页面会显示原因。确认依赖服务恢复后点击“刷新数据”，不要将加载失败当成没有记录。
- **联系电话重复：** 使用未登记过的测试号码，或直接使用已有档案。
- **工单操作冲突：** 检查当前状态，刷新后查看最新详情，不要对已处理工单重复审核或接单。
- **依赖不可用：** 可能显示 HTTP 503。当前设计不会绕过依赖校验继续新增工单。
- **身份与权限：** 当前在同一课程工作台模拟住户、物业和维修人员，尚未实现业务登录、角色授权及数据范围限制。
- **业务范围：** 已接单仅表示受理完成，维修完工、验收、预约、报价、库存和支付尚未实现。

Nacos 控制台地址为 <http://192.168.158.128:18088/>，用于展示服务注册与实例状态，不是工单列表，也不等于业务登录系统。
